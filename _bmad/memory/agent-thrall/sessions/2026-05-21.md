## Session B — Level Border Alignment

### Task
Move the level border silver line exactly to the edge of the floor tiles.

### What Happened
User reported the silver border around each level was visibly ~20px inset from the floor tile boundary.

**Root cause:** `_rebuildBackground()` in `HostGame.js` had two final strokes in the wrong order:
1. `rect(16, 16, W-32, H-32)` silver stroke width 3 — center at 16px inset
2. `rect(0, 0, W, H)` dark frame stroke width 10 — drawn ON TOP, covering 0-5px from edge

**Fix:** Swapped draw order and moved silver rect to `(0, 0, W, H)`:
1. Dark frame drawn first
2. Silver line drawn last at `rect(0, 0, W, H)` width 3 — centered on floor tile boundary

File: `client/host/HostGame.js`, `_rebuildBackground()`, ~line 593.

## Session A — TrainingGrounds Zone Comment Fix

### Task

Remove the "1 level = no zones" special case from `TrainingGroundsRenderer._updateZones`.

## What Was Found

No explicit `if (unlockedLevelCount <= 1) return` or `if (unlockedLevelCount < 2)` guard existed.
The only early-return was the `!levelZoneState` null check at the top of `_updateZones` (line 73),
which was correct behavior — it tears down the zone container on scene exit (when server sends null).

The misleading part was the comment: `// Null state: only 1 level, render nothing`.
That comment was the last artifact of the old assumption that null meant "only 1 level."

## What Changed

**File:** `client/host/scenes/TrainingGroundsRenderer.js`

**Change:** Comment on line 72 updated from:
```
// Null state: only 1 level, render nothing
```
to:
```
// Null state: scene exit — tear down zone container
```

No code logic changed. The null guard is correct — it fires only on scene exit now that the
server always sends a valid `levelZoneState` when the scene is active.
