# Session 2026-05-20 (two tasks)

## Task

Fix damage and healing meters to record actual HP taken/gained, while keeping floating combat text showing full ability damage numbers.

## What Was Found

`_dealDamage` in `SkillSystem.js` computed `actualDealt` from `target.takeDamage()` return value, but:
- `ServerEnemy.takeDamage` returned `undefined` (no return statement)
- `ServerBoss.takeDamage` returned `undefined` (no return statement)
- So `actualDealt` fell back to `finalAmount` via `?? finalAmount` — HP capping was invisible

Meter then recorded `finalAmount` anyway (same bug, double). Result: overkill damage counted in full.

Healing: `ServerPlayer.heal()` did not return actual HP gained. All 10 `_trackHeal` call sites passed the raw ability amount. Heals on full-HP players fully credited.

## Design Decision (Cyby)

Floating text = `finalAmount` (ability damage, pre-HP-cap — "what the skill did")
Meters = `actualDealt` / actual HP gained ("what really happened to the target")
These are now explicitly separated at the emit site and the stat tracking site.

## Changes Made

- `server/entities/ServerEnemy.js` — `takeDamage` returns `Math.min(amount, this.hp)`
- `server/entities/ServerBoss.js` — same
- `server/entities/ServerPlayer.js` — `heal` returns `this.hp - before`
- `server/systems/SkillSystem.js`:
  - VFX emit: `amount: finalAmount` (was `actualDealt`)
  - Meter tracking: `actualDealt` (was `finalAmount`)
  - `_dealDamage` return: `actualDealt` (affects lifesteal base — now correctly no overkill credit)
  - All 10 `_trackHeal` call sites: capture `heal()` return value, pass to `_trackHeal`

## Task 2: Result screen disconnect bug + run history system

### Root Cause Analysis

**Bug 1 — Disconnected players vanish from result roster:**
`ResultScreen.svelte` read `players` from live `state.players`. On non-battle disconnect (result screen is non-battle), `_onDisconnect` deletes the player and emits `PLAYER_LEFT`. Client removes from map. Player gone from roster.

**Bug 2 — Stats orphaned on reconnect:**
Stats keyed by socket ID (`player.id = socket.id`). `_reclaimPlayer` updated `player.id` to new socket ID but did NOT re-key `this.stats.damage/heal/etc`. Old socket ID entry orphaned. Reconnected player shows 0 damage even though they dealt damage before disconnect.

### Fix: Snapshot at scene transition

`_changeScene('result'/'gameover')` now includes `playerSnapshot` in `cumulativeStats` payload — array of `{ id, name, className, isDowned }` captured at level-end, before any disconnect can modify the player map.

`ResultScreen.svelte` uses `stats?.playerSnapshot ?? live players` — always renders the frozen roster.

### Fix: Stats re-keying on reconnect

`_reclaimPlayer` now re-keys all stat maps (damage, heal, deaths, resurrections — both cumulative and levelStats) from `oldId → socket.id` before updating `player.id`. Stats follow the player across reconnects.

### New: RunHistory module

`server/RunHistory.js` — ring buffer (50 entries). `recordLevel(levelIndex, levelName, outcome, stats, playerSnapshot)`:
- Re-keys stats from socket ID → player name for cross-session stability
- Called at: `_doLevelComplete` (victory, per level), NPC-died gameover, `_checkAllDead` gameover
- Snapshot captured BEFORE `currentLevel = null` (important for gameover paths)

### Changes Made

- `server/RunHistory.js` — new file
- `server/GameServer.js`:
  - Import RunHistory, `this.runHistory = new RunHistory()` in constructor
  - `_buildPlayerSnapshot()` — helper that captures non-host player snapshot
  - `_reclaimPlayer()` — added stat re-keying (7 maps)
  - `_onHostAdvance()` result path — now includes `cumulativeStats + playerSnapshot`
  - NPC-died gameover — snapshot + record before nulling currentLevel
  - `_doLevelComplete()` — snapshot + record, pass snapshot in result payload
  - `_checkAllDead()` — snapshot + record before nulling currentLevel
- `client/host/components/ResultScreen.svelte` — `players` uses `stats?.playerSnapshot` fallback
