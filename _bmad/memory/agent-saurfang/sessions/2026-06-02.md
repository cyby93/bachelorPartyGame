# Session 2026-06-02

## Task
iPhone joystick (MoveJoystick + SkillButton nipplejs) occasionally freezes on iOS with rare occurrence. Previous fixes: `touchcancel` handler + watchdog (MoveJoystick), `pointercancel` joystick cleanup (SkillButton), `touch-action: none`. Bug still surfaces.

## Root Cause Analysis

**`touchcancel` covers system-interrupted touches** (phone call, Siri, alert) but **does NOT fire reliably on iOS when the user presses the home button or invokes the app switcher.** In that scenario, only `document.visibilitychange` (hidden) and `window.blur` fire. Neither file handled these events.

Secondary issues:
- Watchdog threshold was 10 seconds — unacceptably long freeze window before auto-recovery
- `multitouch: false` missing — nipplejs could attempt to process multi-finger input on the same zone (nipplejs issue #94)

## Changes

### MoveJoystick.svelte
- Added `_visHandler` (`document.visibilitychange`) and `_blurHandler` (`window.blur`) both calling `_reset()` (zero vec + recreate joystick)
- Handlers stored as module-level vars, cleaned up in `onDestroy`
- Watchdog threshold: `10000 → 3000ms`
- Added `multitouch: false` to nipplejs.create options

### SkillButton.svelte
- Added new `$effect` that registers `visibilitychange` + `blur` listeners
- On page hidden: mirrors `onPointerCancel` path for DIRECTIONAL/TARGETED/AIMED types (clear heartbeat, autoFire, emit END/cancelCast), and `onPointerUp` path for INSTANT/SUSTAINED
- Effect returns cleanup removing both listeners

## Result
Three-layer defense now:
1. `touchcancel` — system-interrupted touch (phone call, notification, alert)
2. `visibilitychange` / `blur` — app switch, home button, app switcher
3. Watchdog (3s) — any remaining unknown iOS nipplejs bug where both signals fail
