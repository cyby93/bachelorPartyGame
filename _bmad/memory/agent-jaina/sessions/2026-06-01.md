## Task

Added a player presence ring to `CreationScreen.svelte`. While the host waits on the QR code screen, connected players' names now float around the screen edges with class-colored spotlight backgrounds.

## Decisions made

- **Ready phase only** — pills invisible during loading/click-to-continue phases
- **Guests only** — `!isHost && !isBot` filter; host is already present by running the screen
- **No count badge** — edge names are the only indicator (count is implicit)
- **Neutral grey** (`#888888`) for players who haven't selected a class yet; color updates reactively when they do
- **13 fixed EDGE_SLOTS** — pre-defined positions (4L, 4R, 3T, 2B) to avoid layout shifts as players join one by one; assigned in stable ID-sort order
- **Two-div anchor/pill pattern** — outer `edge-anchor` handles `position: fixed` + centering transform; inner `edge-pill` handles float animation; avoids CSS transform collision
- **Radial gradient spotlight** — replaced chip background with `radial-gradient(ellipse at center, ...)` fading to transparent; looks like a colored flashlight aimed at the name
- **Text shadow** — soft matching-color glow on the name text for the "lit from behind" look
- **Font 22px / weight 700** — 2× the original 11px chip size

## Files changed

- `client/host/screens/CreationScreen.svelte` — script additions (CLASSES import, EDGE_SLOTS, guests derived, pillEntries derived), template block inside `.creation-screen`, CSS for `.edge-anchor`, `.edge-pill`, `@keyframes pill-float`

## What worked well

Two-iteration polish: spec → implement → user requested bigger text + spotlight redesign → single CSS block edit. Clean separation between anchor (positioning) and pill (visual) made the redesign trivial.

## Session 2 — Ability Briefing & Upgrade View pre-release audit

## Task
Final pre-release review: verify AbilityBriefing.js descriptions and UpgradeSelectScreen.svelte display logic match SkillDatabase.js final numbers.

## Bugs Found and Fixed

### AbilityBriefing.js — 7 factual description errors (all fixed)
1. **Thunder Clap**: "50% slow for 2s" → "70% slow for 3.5s" (speedMultiplier 0.3, duration 3500ms)
2. **Hammer of Light**: "Every 3rd hit" → "Every 4th hit" (procEvery: 4)
3. **Bloodlust**: "by 30%" for both → speed +20% (1.2x), attack rate +50% (1.5x)
4. **Call of the Wild**: "20 seconds" → "15 seconds" (duration: 15000)
5. **Frost Nova**: "2 seconds" → "4 seconds" (effectParams.duration: 4000)
6. **Blink**: "250 units" → "200 units" (distance: 200)
7. **Vanish**: "5 seconds" → "4 seconds" (duration: 4000)

### UpgradeSelectScreen.svelte — display logic bugs (both fixed)
- **LOWER_IS_BETTER** was missing `tickRate` and `chargeDuration` — reductions for these paths showed as red (bad) when they're buffs
  - Tranquility +3 (tickRate -50), Shield Block/Divine Protection all tiers (chargeDuration reductions)
- **TIME_PATHS** updated to include `chargeDuration` and `tickRate` for proper "s" formatting
- **PATH_LABELS** added 7 missing entries: `trapEffect.zoneDuration`, `damageBonus`, `shieldReduction`, `shieldAbsorbThreshold`, `arc`, `chargeDuration`, `lifesteal`

## Not Fixed (flagged only)
- UpgradeConfig.js internal comments cite base values that diverge from current SkillDatabase — pervasive across every class. Not user-facing, but misleading for future tuning. Recommend a separate sync pass.

- ClassConfig HP/Speed values — feed directly from ClassConfig at render time ✓

- All 40 ABILITY_LABEL gesture labels covered ✓
