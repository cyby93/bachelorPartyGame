# Session 2026-05-28

## Changes Made

### 1. Illidari Centurion — no melee damage while dazed
**File:** `server/GameServer.js:1948`
Added `&& e._chargeState !== 'dazed'` to the contact damage guard. `_chargeState` is initialized to `'idle'` for all enemies, so the check is safe across the board.

### 2. Blood Prophet — puddle radius from config
- `shared/EnemyTypeConfig.js` — added `puddleRadius: 60` to `bloodProphet`
- `server/entities/ServerEnemy.js` — constructor reads `this._puddleRadius = base.puddleRadius ?? 60`; also added `this.isRanged = base.isRanged ?? false` here
- `server/entities/ServerEnemy.js:_aiBloodProphet` — teleport action now includes `puddleRadius: this._puddleRadius`
- `server/GameServer.js:2113` — `addZone` call uses `action.puddleRadius ?? 60` instead of hardcoded 60

### 3. Hunter pets: enemies never target hawk
**File:** `server/entities/ServerEnemy.js:_findNearest`
Added `if (m.chosenBeast === 'hawk') return` inside the minions loop. The hawk is invincible and was being selected as the nearest target by enemies when physically closest.

### 4. Hunter pets: panther/bear target correct enemy class
Root cause: `_findNearestRangedEnemy` and `_findNearestMeleeEnemy` in `ServerMinion.js` used `_attackRange` threshold (>100 / ≤100). But brute/centurion/etc. had default `_attackRange = 300` (no explicit config), so they were falsely identified as ranged.

Fix: Added explicit `isRanged: true` flag to harpooner, mystic, and bloodProphet in `EnemyTypeConfig.js`. Updated both helper methods to check `e.isRanged` directly.

### 5. Hunter Freezing Trap — spawn under player, not next to player
**File:** `server/systems/SkillSystem.js:_executeSpawn` (~line 766)
All minions were spawning at `player.x + v.x * 30, player.y + v.y * 30` (offset in facing direction). Added `isTrap = config.subtype === 'TRAP'` discriminator; TRAPs now spawn at `player.x, player.y` exactly. TOTEM, PET, WILD_BEAST keep the offset.

None for this session — these are pure server-side logic changes.
