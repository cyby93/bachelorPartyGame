## Session — Icebound Fortitude damageReduction not resetting

**What happened:** Fixed a bug where Icebound Fortitude's 60% damage reduction persisted permanently after the effect faded.

**Key outcomes:**
- Root cause: `takeDamage()` in `ServerPlayer.js` removes the Icebound Fortitude `activeEffects` entry when `shieldAbsorb` hits 0, but never calls `rebuildStats`. So `damageReduction` stays at 0.6. Later when the timer fires, `activeEffects.length` is unchanged — `rebuildStats` is skipped again. Reduction is stuck forever.
- Fix: added `rebuildStats(this)` immediately after the `activeEffects.filter` inside the `shieldAbsorb === 0` branch. One line, `ServerPlayer.js:138`.
- Side effect is correct: overflow damage from the hit that depleted the shield is no longer reduced — effect is fully gone at depletion.

**Observations:** `rebuildStats` was already imported in `ServerPlayer.js`. The expiry path (timer fires) was already correct; the only broken path was shield-depletion-before-expiry.

**Follow-up:** None. Clean fix, no open questions.

## Session — Sinister Strike rect hitbox edge-miss bug

**What happened:** Melee rect was doing a point-in-rect test against enemy center; hits registered only when center was inside the rectangle, not when the enemy body (oval) overlapped the rect edge.

**Key outcomes:**
- `CollisionSystem.inOrientedRect()`: added optional `targetRadius = 0` param. When > 0, uses closest-point expansion: clamps `(forward, lateral)` to rect bounds, computes dist² from target center to that closest point, returns true if `dist² <= targetRadius²`. This is a rect-vs-circle overlap check in the rect's local frame.
- `SkillSystem._executeMelee()`: `_inHitbox(tx, ty, tr = 0)` now accepts a radius; all four hit loops pass the target's `.radius` (enemies, boss, gates, buildings). Cone path ignores the radius (unchanged — point check only, no reported issues there).

**Observations:** Training dummy radius = 30 (from EnemyTypeConfig). Enemy oval stores `radiusX = radius/2`, `radiusY = radius` — but the collision expansion uses `.radius` (the larger axis), which is intentionally generous and consistent with other server collision checks.
## Session — Holy Nova sticky autoRefire

**Report:** Holy Nova (Priest INSTANT + autoRefire) kept firing after user dragged finger off the button and released outside.

**Root cause:** Two problems:
1. `.skill-btn` had no `touch-action: none` — mobile browsers could hijack the touch gesture and break implicit pointer capture, so `pointerup` was never routed back to the button.
2. No fallback cleanup path if `pointerup`/`pointercancel` didn't fire on the element.

**Fix (`client/controller/components/SkillButton.svelte`):**
- Added `touch-action: none` to `.skill-btn` CSS.
- Extracted `clearAutoRefire()` helper that clears both the interval AND deregisters window listeners.
- In `onPointerDown` (autoRefire path): register `window` `pointerup`/`pointercancel` listeners filtered by `e.pointerId` — guarantees cleanup regardless of where the finger lifts.
- Replaced all bare `clearInterval(autoFireInterval)` calls with `clearAutoRefire()` in `onPointerUp`, `onPointerCancel`, `onDestroy`.

**No server changes needed.**

## Session — Level Entry/Exit Cinematic System

**What was built:**

### New: `server/systems/CinematicMovementSystem.js`
Generic server-side scripted player movement. Linear lerp from start → target over fixed duration. Two static factory methods:
- `buildWalkInTargets(players, arenaWidth, arenaHeight)` — 13-slot V-formation, sets `player.x = -60` off-screen
- `buildWalkOutTargets(players, arenaWidth)` — living players target `arenaWidth + 60`

`tick(dt)` must run AFTER `p.update(dt)` + wall collision to overwrite boundary clamping.

### Modified: `server/GameServer.js`
- `this._cinematicSystem` added to constructor + `_clearCombatState`
- `_startLevel()`: walk-in setup replaces random spawn scatter; `deferToWalkIn` flag gates spawn system and dialog start timing
- New `_onWalkInComplete(level, playerCount)`: creates SpawnSystem + starts dialog
- New `_placePlayersInFormation()`: instant teleport to formation, used when `skipDialog=true`
- `_onLevelComplete()` → walk-out wrapper; original body moved to `_doLevelComplete()`
- `_gameTick()` step 2c: cinematic tick runs after wall collision
- Input suppressed in `_onInputMove`, `_onInputSkill`, `INPUT_AIM`, `_processSkillInput`, and input drain loop

### Modified: `shared/LevelConfig.js`
All 6 levels: `transition.opening.walkInMs = 2500`, `transition.closing.walkOutMs = 2000`. Removed `enemySpawnDelayMs` (spawn system now created in walk-in callback).

**Key design decisions:**
- Cinematic tick after `p.update()` + wall collision is critical — boundary clamp at x < 0 would fight the off-screen positions otherwise
- Level 5 ambient spawning now deferred to walk-in complete (was immediate at t=0)
- Walk-out clears `enemies` + `projectiles` before starting so nothing attacks during exit
- `_levelCompletePending` guard prevents duplicate walk-out creation

**Follow-up:** Jaina may want to suppress ability cooldown HUD during the walk-in window (optional cosmetic). No mandatory client changes needed — walk animation auto-triggers from position delta.
