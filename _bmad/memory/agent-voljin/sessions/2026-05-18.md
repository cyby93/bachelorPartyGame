# Session 2026-05-18

## Task

Fixed projectile impact sounds falling through to generic fallback (bow impact / flesh-hit) for all payload-based player skills (Fireball, Lightning Bolt, Shadow Bolt, etc.).

## Root Cause

`_executeCastPayload` in `server/systems/SkillSystem.js` builds a config object from the skill's `payload` sub-object when spawning a PROJECTILE. That sub-object has no `name` field — the name lives on the parent skill config. `_spawnProjectile` reads `config.name ?? null` for `sourceSkill`, so all payload-spawned projectiles got `sourceSkill: null`.

On hit, `_dealDamage` passed `null` as sourceSkill → server emitted `effect:damage` with `sourceSkill: null` → AudioManager `handleEffectDamage` hit the `!data.sourceSkill` branch → played `sfx_skill_shoot_bow_impact` regardless of actual skill.

## Fix

- Added `skillName = null` parameter to `_executeCastPayload`.
- Added `name: skillName` to the projectile config object passed to `_spawnProjectile`.
- Updated all 4 call sites to pass `config.name ?? null` or `cast.config.name ?? null`.

## Files Changed

- `server/systems/SkillSystem.js` — lines 470, 1564, 1573, 1662, 1756-1762

## Notes

The AudioConfig skill audio map (`buildSkillAudioMap`) and AudioManager impact handlers were both correct. The entire bug was in the server not threading skill identity into the spawned projectile. No audio-side changes needed.
