# Session 2026-05-21

## Task

Two modifications to `_tickZoneSelector` in `server/GameServer.js`.

## Changes Made

### 1. Always run zone selector — removed early-return guard

Removed the block at the top of `_tickZoneSelector` that returned early and nulled `_levelZoneState` when `unlockedLevelCount <= 1`. The method now always runs. With `unlockedLevelCount = 1`, there is one zone covering the full arena width, so the majority vote immediately fires.

The `StateSerializer.js` did not need changes — the scene gate (`gs.scene === 'trainingGrounds'`) already correctly controls when the value is emitted. The null case was only an artifact of the early-return guard which is now gone.

### 2. Auto-start campaign on commit — no host button needed

Changed the commit block to call `this._startCampaign()` when countdown hits zero. Added the `prev?.committedIndex === null` guard so it only fires once (not on every subsequent tick). Sets `_levelZoneState` to the final committed state before calling `_startCampaign()` so the state is broadcast once before scene changes away.

```js
if (pendingIndex !== null && this._zoneCountdownMs === 0 && prev?.committedIndex === null) {
  committedIndex = pendingIndex
  this.startingLevelIndex = committedIndex
  this._levelZoneState = { counts, pendingIndex, countdownMs: 0, committedIndex }
  this._startCampaign()
  return
}
```

`_onEnterRaid`, `_startCampaign`, and quiz logic untouched.
