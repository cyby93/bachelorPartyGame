## Session — BuildingSpawnSystem global cap fix

**What happened:** Cyby identified that `maxTotalAlive` in `buildingSpawning` config was not working as a global level cap. The system distributed it to per-building caps via `ceil(maxTotalAlive / aliveBuildings)`, so 4 buildings with `maxTotalAlive: 1` allowed 4 total alive enemies, not 1.

**Key outcomes:**
- Fixed `BuildingSpawnSystem.js tick()`: now sums `_aliveCount` into `totalAlive` before the buildings loop; `maxGlobal` is the hard ceiling; `totalAlive` is incremented inside the spawn loop so later buildings in the same tick respect the cap.
- `maxAlivePerBuilding` remains the fallback per-building cap when `maxTotalAlive` is absent — they are now mutually exclusive modes.
- Fixed Level 3 `LevelConfig.js`: changed `maxTotalAlive: 1` → `16` (coherent with `countPerSpawn: [3, 4]`).

**Observations:** The original code tried to redistribute the total cap on building death by dividing it among alive buildings. Conceptually sensible, but mathematically wrong when `maxTotalAlive` isn't divisible by building count (and amplified badly with small values). The global sum approach is strictly correct.

**Follow-up:** Cyby should playtest Level 3 to tune `maxTotalAlive: 16`. May want to increase or decrease based on feel.

## Session — Building and gate damage roster tracking fix

**What happened:** Cyby asked to verify whether building damage was added to the damage roster. It wasn't — three of four damage paths bypassed `_dealDamage` entirely. Gates had the same gap. Both were fixed.

**Key outcomes:**
- `ServerBuilding.takeDamage()` and `ServerGate.takeDamage()` now return actual HP dealt (was returning undefined).
- All four building damage paths (melee, AOE, projectile, DoT) now write to both `gs.stats.damage` and `gs.levelStats.damage`.
- All three gate damage paths (melee, AOE, projectile) wired the same way.
- AOE gate hits were also missing a `effect:damage` VFX emit — added.
- Projectile gate hits were not applying `damageMult` — fixed (buildings had it, gates didn't — inconsistency).

**Observations:** The structural root cause: buildings and gates are not valid targets for `_dealDamage` (which is wired for enemies/boss/players), so every call site does manual `takeDamage()` calls. Manual = easy to forget stat tracking. The fix is correct but fragile — any future new building/gate damage path will need the same boilerplate. Worth a comment in code, or a helper method on the server.

**Follow-up:** Consider `_dealStructureDamage(gs, attacker, structure, amount)` helper to centralize this pattern and prevent future omissions.
