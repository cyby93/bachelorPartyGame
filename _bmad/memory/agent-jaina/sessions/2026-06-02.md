The inline `<style>` block in controller.html comes after the `<link>` tags, so it wins by CSS source order. The font-family had to be updated both in base.css (canonical) and in the inline style (override). The inline style remains because it carries mobile-specific rules (`user-select`, `touch-action`) that must not be lost.

## Architecture note
Controller now mirrors host: HTML links tokens.css + base.css; base.css owns font declarations.

## Task 3 — Screen Wake Lock review and fix

### Findings
Wake lock was already in `client/controller/App.svelte` (lines 49–54, 100–104, 254–257). Missing piece: `release` event listener on the sentinel. Without it, if the browser releases the lock for non-visibility reasons (battery saving, OS override), `wakeLock` stays stale and `onDestroy` calls `.release()` on an already-released sentinel.

`nosleep.js` v0.12.0 was in `package.json` but never imported — dead legacy dependency that predates the native Wake Lock API.

Host side has no wake lock code anywhere. Correct, untouched.

### Changes
- `client/controller/App.svelte` — expanded `requestWakeLock()` to add `release` listener: `wakeLock.addEventListener('release', () => { wakeLock = null })`
- `package.json` — removed `nosleep.js` entry, ran `npm install` to sync lock file.
