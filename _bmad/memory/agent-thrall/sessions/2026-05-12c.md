# Session 2026-05-12c — Fireball & Pyroblast sprite wiring

## What happened

Cyby asked for the best PixelLab solution to create a fireball sprite for the mage.

Found that `projectile_fireball.png` already existed and looked correct (glowing orange-red orb with flame wisps). The real gap was wiring.

### Root cause diagnosis
CAST+PROJECTILE skills need `spriteKey` inside `payload`, not at the skill level.
- `_executeCastPayload` reads `payload.spriteKey`
- Direct PROJECTILE type skills use `config.spriteKey` (top level)
- First attempt put it at skill level → no effect. Fixed by moving into `payload`.

### Changes made

**`shared/SkillDatabase.js`**
- Fireball: added `spriteKey: 'projectile_fireball'` inside `payload`
- Pyroblast: added `spriteKey: 'projectile_fireball'` inside `payload` (shared sprite; larger radius naturally reads as bigger shot)

**`client/host/entities/ProjectileSprite.js`**
- Added `FIRE_COLORS` palette
- Added `PROJECTILE_CONFIG` entry: `{ trailStyle: 'fire', spinSpeed: 0.06, bodyScale: 1.2, trailLength: 6 }`
- Added `_spawnFireEmbers()` — perpendicular scatter, short life (200–400ms), 2 embers/frame
- Added `_drawFireTrail()` — 3-layer heat bloom (deep orange outer, orange mid, bright yellow-white core) + floating ember particles
- Wired into `update()` and `_drawTrail()` dispatch

## Key lesson

**CAST+PROJECTILE spriteKey goes in `payload`, not at skill level.** PROJECTILE type skills use top-level. Always check the execution path before placing fields.
