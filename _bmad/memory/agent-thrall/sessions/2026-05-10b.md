# Session 2026-05-10b — Cooldown Bar System

## What We Built
Replaced the cooldown dot concept with a segmented cooldown bar on the character overhead display for all players on the host screen.

## Design Journey
1. Started with dots (on/off) — Cyby approved option A (no progress fill needed)
2. Switched to dots visible only when on CD, half size (2.5px radius)
3. Replaced dots entirely with a segmented bar — same width as HP bar (44px), divided into N segments per class, fills on CD start, drains to empty as CD expires
4. Multiple layout iterations: below HP bar → above cast bar → finally **below HP bar** (flush)
5. Linter adjusted SEG_H to 4px and barY to `yOffset + HP_BAR_H` (no +1 gap)

## Final Layout (bottom to top above entity)
- **CD bar** — below HP bar (`yOffset + HP_BAR_H`)
- **HP bar** — center anchor
- **Cast bar / Rogue combo pips** — same slot above HP bar (`yOffset - 6`), no class has both
- **Status icons** — above that (`yOffset - 18`)

## Key Design Decisions
- Skills with CD < 2000ms excluded (Shoot Bow 500ms, Sinister Strike 500ms, Obliterate 700ms, Cleave 1000ms, Holy Nova 1000ms) — too fast to be meaningful
- Skills with CD = 0 never trigger the event — no segment created
- `dotColor` field added to each qualifying skill in SkillDatabase.js
- Segments always visible (dark bg 0x111111 alpha 0.6), colored fill drains left-to-right
- Rogue combo pips moved to same Y as cast bar (they never coexist)

## Files Changed
- `shared/SkillDatabase.js` — `dotColor` on all skills with CD ≥ 2000ms
- `client/host/systems/OverheadDisplay.js` — segmented CD bar + `setCooldowns()` + `_drawCdBar()` + combo pip repositioning
- `client/host/entities/PlayerSprite.js` — `_cooldownEnds` tracking `{ endTime, totalMs }` + `onCooldown()` + snapshot passed to overhead
- `client/host/scenes/BaseRenderer.js` — `onCooldown(data)` routes to PlayerSprite
- `client/host/main.js` — `socket.on(EVENTS.COOLDOWN, ...)` listener

## Data Pipeline
Server emitted `skill:cooldown` all along — host client just never listened. No server changes needed. Client tracks `{ endTime, totalMs }` locally, computes `remaining/total` ratio each frame for fill percentage.
