# Session 2026-05-25

## Problem
13-player rooms produce continuous audio noise when players spam abilities. `handleSkillFired` had zero throttle — every SKILL_FIRED event played a cast sound immediately, with no per-family or global cap.

## Solution Implemented
Added a two-layer throttle to `handleSkillFired` in `client/host/systems/AudioManager.js`:

**Gate 1 — Per-family throttle:** `_skillFamilyThrottle` Map tracks last-fired timestamp per audio family. Same family blocked for 200ms. Eliminates same-class stacking (e.g., 3 Hunters all draw bows at once = 1 arrow sound).

**Gate 2 — Global concurrent cap:** `_recentSkillFires` rolling array tracks cast sounds within a 100ms window. If ≥4 fired in that window, new ones are dropped. Mixed-class burst of 13 players → 4 sounds max per 100ms.

**Constants (all in `_throttle` in the constructor — tunable by ear):**
- `skillCastFamilyMs: 200`
- `skillCastMaxConcurrent: 4`
- `skillCastWindowMs: 100`

## Tier System (same session, second task)
Added skill tier system on top of the two gates.

- `SIGNATURE_SKILLS` Set exported from `shared/AudioConfig.js` — edit here to promote/demote.
- `buildSkillAudioMap()` now stamps every entry with `tier: 'signature' | 'combat'`.
- In `handleSkillFired`: signature skills bypass Gate 2 (concurrent cap) and don't consume a slot; they still respect Gate 1 (family throttle).
