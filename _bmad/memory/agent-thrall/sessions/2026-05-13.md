## Trail system improvements (applied to ALL trails)

### Problem diagnosed
`trailLength` had no visible effect because trail points are spaced by server tick distance (~27px at 550px/s), which was larger than the draw radius. Individual dots were visible instead of a continuous smear.

### Solution: `_interpolateTrail(cx, cy, step)` helper
Extracts a shared method that interpolates intermediate positions between every consecutive stored trail point. Step = radius of the trail circle → adjacent circles always overlap by 50%. Returns `{ rx, ry, t }[]` newest-first.

All 5 trail styles (`holy`, `divine`, `ichor`, `fire`, `shadow`) now use this helper. Key properties:
- Fixed radius per style (not shrinking per-index) → uniform tube shape
- Oldest→newest draw order → head always paints on top
- Works regardless of server tick rate or projectile speed

### Per-style radius (the `r` in each `_draw*Trail`)
| Style | `r` multiplier |
|---|---|
| holy | `this._radius * 0.9` |
| divine | `this._radius * 0.85` |
| ichor | `this._radius * 1.1` |
| fire | `this._radius * 0.9` |
| shadow | `this._radius * 0.6` (Cyby tuned) |

## Key lessons
- `trailLength` controls geometric tail length, not density — explain this clearly next time
- For continuous smear: fixed radius + interpolation. For dotted tail: shrinking radius per index
- PixelLab map objects can be re-downloaded at same ID after user edits them in the web UI
