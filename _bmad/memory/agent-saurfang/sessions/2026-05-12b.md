# Session 2026-05-12b

## Task
Fix three server-side gameplay bugs from KNOWN_ISSUES.md.

## Bug 1 — HP reset on defeat (fixed)

**Root cause:** `applyHpUpgrade()` increments both `baseMaxHp` and `maxHp` permanently. `_startLevel` only reset `p.hp = p.maxHp`, leaving the inflated `maxHp` intact across game runs.

**Fix:** In `GameServer.js` `_startLevel`, when `campaignIndex === 0` (new run), reset `p.baseMaxHp = CLASSES[p.className].hp` and `p.maxHp = p.baseMaxHp` before setting `p.hp = p.maxHp`. HP boosts carry over between levels within the same run; wiping resets them.

## Bug 2 — Enemy melee range oval hitbox (fixed)

**Root cause:** All enemies default to `hitboxShape: 'oval'` (set in constructor). `radiusX = radius/2` (horizontal), `radiusY = radius` (vertical). The AI movement stop condition used `PLAYER_RADIUS + this.radius` (euclidean) but contact detection uses the proper oval check `playerHitsEntity()`. Horizontal approach: enemy stopped at `dist = 20 + 30 = 50` but contact fires at `|dx| ≤ 15 + 15 = 30` — enemy was always ~20px too far.

**Fix:** In `ServerEnemy.js`, changed `stopDist = GAME_CONFIG.PLAYER_RADIUS + this.radius` → `stopDist = GAME_CONFIG.PLAYER_RADIUS_X + this.radiusX` in three AI methods: `_aiChase`, `_aiCharger`, `_aiLeviathan`. Values: `PLAYER_RADIUS_X = 15`, `radiusX = radius/2` for ovals. This aligns stop distance with horizontal contact threshold.

**Note:** No enemy type has `hitboxShape: 'circle'` — all are oval.

## Bug 3 — Game-end condition with bots (fixed)

**Root cause:** `_checkAllDead()` counted only `!p.isHost && !p.isBot && !p.isDead`. When 1 human player died with bots still alive, livingCount hit 0 and triggered game over.

**Fix:** Removed `!p.isBot &&` condition — now counts all non-host living players (bots included). Game ends only when every character, bot and player, is dead.
