# Session 2026-05-20

## Issues addressed

### 1. Penance self-cast cannot heal caster

**Bug:** Self-cast BURST projectiles spawn with `vx=0, vy=0, selfCast=true`. In `_tickProjectiles`, they hit an early-return guard that deletes them before the ally collision/heal check runs. Heal never applied.

**Fix:** Before the early return, apply `healAmount` directly to the owner player when `canHitAllies && healAmount > 0`. Each of the 3 burst projectiles heals the caster independently (22 × 3 = 66 total), which matches how Penance works against allies.

**File:** `server/systems/SkillSystem.js` ~line 1069

---

### 2. Revive progress bar resets when reviver moves or casts

**Root causes (two separate mechanisms):**

1. **Iteration-order instability** — `reviver` was selected as the first alive player in Map insertion order within `REVIVE_DISTANCE`. If another player was closer in insertion order and briefly entered range, `reviverId` changed → timer reset to `startedAt: now` → bar back to 0.

2. **One-tick exit** — if the reviving player moved near the boundary of `REVIVE_DISTANCE` (80px) and crossed it for even one 50ms tick, `reviver = null` → `reviveTimers.delete` → bar reset.

**Fix:**
- **Prefer existing reviver first**: before scanning all alive players, check if the current timer's `reviverId` is still in range. Only fall back to a new player if they're not.
- **Grace period**: added `lastSeenAt` field to the timer. If `reviver = null`, wait 300ms before clearing the timer. If the same player returns within that window, the revive resumes as if nothing happened. The bar continues to show incremental progress during the grace window (at most 15% false advance for a 2s revive) — acceptable tradeoff.

**File:** `server/GameServer.js` `_checkRevive()`

---

### 3. Ability joystick (and possibly movement joystick) stuck on iPhone

**Root cause:** iOS issues a `pointercancel` event when a touch leaves an element boundary without pointer capture (especially during rapid double-tap + drag sequences). nipplejs may fail to fire its own `end` event in this scenario. `onPointerCancel` in `SkillButton.svelte` was returning early for DIRECTIONAL/TARGETED/AIMED types without cleaning up `joystickHeld`, `aimHeartbeat`, or `autoFireInterval`. These stayed active indefinitely.

**Fix:**
- **SkillButton.svelte `onPointerCancel`**: when `joystickHeld` is true, perform the same cleanup that `j.on('end', ...)` does — clear intervals, clear `joystickHeld`, emit END for SHIELD/cancel for castBar. Sets `lastDistance = 0` so if nipplejs's own `end` fires afterward, it won't fire a stale shot.
- **MoveJoystick.svelte**: added `touch-action: none` to `.move-zone`. Without this, the browser can hijack movement gestures as scroll on iOS, preventing `touchend`/`pointerup` from reaching nipplejs.

**Files:** `client/controller/components/SkillButton.svelte`, `client/controller/components/MoveJoystick.svelte`
