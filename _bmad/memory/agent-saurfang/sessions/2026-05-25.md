## Session — Bloodlust stacking fix

**What happened:** Cyby reported that multiple Shamans casting Bloodlust simultaneously caused multiplicative stacking (1.5× × 1.5× = 2.25×) because each cast pushed a separate `activeEffects` entry.

**Key outcomes:**
- Fixed in `server/systems/SkillSystem.js` BUFF handler (~line 829).
- Before pushing a new buff entry, check if `p.activeEffects` already has an entry with `source === 'aoe_buff'` and `skillName === config.name`.
- If already active: refresh `expiresAt` and minion `_hasteExpiresAt` only — skip push, `rebuildStats`, and `compressPlayer`.
- If not active: full application path as before, plus `skillName` is now tagged on the pushed entry for future dedup lookups.
- This is a generic fix: any future `effectType === 'BUFF'` AOE skill is protected from stacking by the same logic.

**Observations:** The existing `activeEffects` architecture had no identity on buff entries — just `source: 'aoe_buff'`. Adding `skillName` to the entry is minimal and correct; it doesn't affect `rebuildStats` since that only reads `params`.

**Follow-up:** None. Fix is complete and self-contained.
